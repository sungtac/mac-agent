# verify-task-stop-check.sh

`hooks/verify-task-stop-check.sh` — a Claude Code `Stop` hook. Registered in `~/.claude/settings.json` under `hooks.Stop`, it fires every time a session ends (including `/clear`, `/resume`, `/compact`). It's a **mechanical proxy, not real judgment**: it can't tell a good edit from a bad one. It has two tiers:

- **MANDATORY category registry (2026-07-27, user-confirmed)** — no escape valve. If the session matches one of these and `verify-task` never appears in the transcript, the hook blocks unconditionally; "this was too light to need it" is not an accepted reason. Grown **one item at a time** as the user identifies more:
  1. **코딩 (coding)** — 3+ `Edit`/`Write` tool calls this session.
  2. **아이디어 회의 (idea/design meeting)** — `ExitPlanMode` invoked this session. This is the best mechanical proxy available right now, not a solved detector — a design/idea discussion that never enters Plan Mode isn't caught yet. If that gap matters in practice, the fix is either a better signal or making Plan Mode mandatory for design discussions, not loosening this hook.
- **SOFT category (pre-existing)** — a risky `Bash` command (git commit/push, brew/npm/pip install, plugin install, marketplace add, rm -rf, chmod +x) with none of the mandatory categories hit. Escape valve intact: the agent may explain to the user why verification was skipped instead of running it.

Nags **at most once per session** (tracked via a marker file in `~/.claude/hooks-state/verify-task-nag/`) so a genuinely-trivial session can't get stuck in a loop — this applies to both tiers equally; "at most once" limits the *nag*, not the mandatory tier's substance.

- **Why code, not just memory:** relying on the agent to just remember to run `verify-task` was demonstrably forgotten in practice (see the HWPX plugin install task, 2026-07-24) — the user asked for this to be enforced mechanically instead so it can't be silently skipped. The mandatory-tier split (2026-07-27) exists for the same reason one level up: "I judged this needed verification" was itself becoming a self-granted excuse (same day as the `docs/usage-routing.md` Rule A rework, for the identical reason) — so 코딩/아이디어 회의 are pulled out as named, checkable categories with zero self-report exit, while everything else stays a softer nag.
- **Deliberately `command`, not `prompt`/`agent`:** Claude Code's `Stop` hooks actually do support `type: "prompt"` (routes to a quick Claude call) and `type: "agent"` (spawns a real subagent) — verified 2026-07-25, correcting an earlier wrong claim in this doc that `command` was the only option here. This hook stays `command` anyway: it's a cheap, fast, deterministic pre-filter that runs on *every* session end, and `prompt`/`agent` types would mean an LLM call on every single Stop event just to maybe decide "no verification needed" — not worth the latency/cost for what's meant to be a lightweight mechanical gate. So this hook is a blunt keyword/count heuristic on purpose, not genuine judgment — false positives (nagging on trivial sessions) and false negatives (missing substantive work that doesn't match the heuristic) are both possible, and both are considered an acceptable trade for staying cheap and instant.
- To port to another agent/machine: add the same `hooks.Stop` entry (command: `bash <path-to-this-repo>/hooks/verify-task-stop-check.sh`) to that machine's `~/.claude/settings.json`.

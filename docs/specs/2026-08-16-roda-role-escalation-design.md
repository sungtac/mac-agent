# 로다 역할 재정립 + 인시던트 에스컬레이션 설계 (브레인스토밍 결과)

- 상태: 브레인스토밍 완료, 구현 계획(writing-plans) 미착수
- 관련 브레인스토밍 주제: "텔레그램 단체방에서 로다의 역할 재정립과 에이전트들과의 협력 방안에 대한 고찰" (2026-08-16 시작)

## 배경

- 로다(roda-gemma)는 텔레그램 단체방에서 Claude(맥)·Codex·Antigravity와 함께 fan-out으로 반응하는
  4번째 에이전트. 슬래시 커맨드엔 반응 안 함.
- 실제 역량은 있음 — "2명 정족수" 토론에서 3단계 위험분류를 독자적으로 제안한 사례.
- 하지만 태생이 "인프라 알림봇"이라 대화 참여자로 잘 안 여겨지고, 헬스모니터
  (`~/.edge-agent/state/telegram-health-monitor.json`)에 열린 인시던트가 11건 쌓여 방치되는
  중 — 로다가 뭔가 감지해도 그 뒤 문제 해결로 이어지는 연결고리가 없었음.

## 결정 사항

### 1. 인시던트 처리 4단계 체인

1. **규칙 기반 1차 라우팅**: 인시던트 타입 → 담당 에이전트 고정 매핑
   (`main-dirty` → 그 파일의 레포 소유 에이전트, `*_service_down`/`*_execution_error` →
   로그에 찍힌 그 에이전트 자신). 매핑에 걸리면 로다가 그 에이전트를 직접 호출, 디벨리버레이션 없음.
2. **수락(ack) 대기 — 5분(300초)**: 담당 에이전트가 "확인했다/처리 중" 응답을 5분 내에
   안 하면 무응답으로 간주. 기존 `NO_RESPONSE_SECONDS`/`RECOVERY_TIMEOUT_SECONDS`(300초)와
   동일한 값으로 맞춰 기존 관례와 일관성 유지.
3. **완료 대기 — 24시간**: 수락은 했지만 실제 조치(커밋/병합/재기동)가 24시간 내 안 끝나면
   무응답과 동일하게 처리. 기존 `PENDING_MERGE_TTL_SECONDS`/`MAIN_DIRTY_ALERT_INTERVAL_SECONDS`
   (24시간)와 동일한 값.
4. **안티그래비티 승격**: 2·3단계에서 실패하면 안티그래비티가 조정자로 개입 —
   - 원인 재분류: (a) 담당자가 다운/에러 상태 → 그 자체를 새 인시던트로 사람에게 즉시 알림,
     (b) 매핑이 틀렸음(실제 책임자가 다름/여러 에이전트 얽힘) → 올바른 담당자에게 재호출(1회만,
     무한루프 방지), (c) 담당자는 멀쩡한데 판단이 어려움 → 5번으로.
   - 안티는 직접 코드를 고치는 주체가 아니라 감별 + 재라우팅 + 소집 역할.
5. **풀 디벨리버레이션**: 안티가 (c)로 확정하면 기존 `delib-*` 방식(맥·코덱스·안티·로다
   2라운드 토론)을 소집. 안티가 소집 트리거를 맡음(현재는 이 트리거 주체가 불명확했음).

### 2. 중복 인시던트 병합

- 저수준 dedupe는 기존 코드에 이미 있음(`_fingerprint(role, code, line)` + `alerted` 딕셔너리,
  `main-dirty`는 `MAIN_DIRTY_ALERT_INTERVAL_SECONDS` 일 단위 버킷).
- 없던 것: 같은 근본 원인이 서로 다른 fingerprint로 쪼개지는 경우(예: codex 프로세스가 죽으면
  `execution_error`도 뜨고 몇 분 뒤 `service_down`도 뜸). **같은 `role`에 대해 이미 열린
  인시던트가 있는 상태에서 새 인시던트가 5분(ack 기한과 동일 창) 내에 발생하면, 별도
  에스컬레이션으로 안 올리고 기존 인시던트에 관련 증상으로 첨부.**

### 3. 반복 실패 시 자동 에스컬레이션

- 대상은 "한 인시던트 안에서의 반복"이 아니라 **같은 문제가 시간을 두고 재발하는 경우**
  (한 인시던트 체인 안의 반복은 위 4단계 체인 자체가 이미 에스컬레이션으로 귀결됨).
- 규칙: 같은 `(role, code)` 조합이 기존 `ALERT_RETENTION_SECONDS`(7일) 창 안에서 이미
  풀 디벨리버레이션까지 갔던 이력이 있는데 또 발생하면 → 에이전트 체인(1~5단계) 전부
  건너뛰고 바로 사람에게 알림. "고쳤다고 했는데 안 고쳐진 것"은 에이전트 판단을 못 믿을
  신호이므로.

### 4. 로다의 역할 — "감지는 넓게, 발언은 좁게"

- 검토한 4방향: ①당직 모델(상시 관찰자) ②전문 채널 모델(스코프 극도로 좁힘) ③로다-맥
  역할 분담 재설계 ④로다를 맥의 손발로 통합(독립 인격 제거).
- 결론: **①+②의 절충**. 로다가 대화·로그를 감지하는 범위는 넓게(당직 모델) 유지하되,
  실제로 개입/발언하는 범위는 위 1~5단계 라우팅 규칙을 통과한 것만(전문 채널처럼 통제됨).
  잡담에 끼어드는 로다가 아니라 "인시던트로 확인된 것만 규칙대로 말 거는 로다".
- ③은 이 구조 안에서 자동으로 해소됨 — 로다는 감지·1차 라우팅, 맥은 명시 호출 시 깊이 있게
  응답, 이미 경계가 나뉨.
- ④는 배제 — 안티·코덱스와 대등하게 협업하는 구조를 짰으므로 로다도 독자적 참여자로 남는다.

## 부수 성과

- 안티그래비티 헤드리스 버그 원인 발견·해결: `agy --print`에 `--mode plan`을 붙이면
  헤드리스 권한 프롬프트에 막혀 죽음. 순수 의견 요청엔 `--mode plan` 빼고 쓰면 됨
  (프로덕션 파이프라인 `edge-agent-provider.sh`는 원래 안 붙이고 있었음, 재현 후 확인).
